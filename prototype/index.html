PRD: Multi-tenant SSO & Privilege Demotion Guardrails

Lead PM: Abuzar Siddiqui
Release: Sprint 42
Status: Under Review
Target SLA: Immediate (< 200ms)
💡
Executive Summary: Enterprise HR customers (Acme Corp, Stripe Labs) require strict SOC2 Type II compliance. Currently, when an administrator's privileges are modified or revoked, cached OAuth refresh tokens can linger for up to 60 minutes. This PRD specifies real-time revocation across all multi-tenant endpoints.

1. Problem Statement & Customer Impact

During quarterly security reviews, enterprise clients noticed that access to confidential payroll and compensation bands persisted after role demotions. QA scenario TC-402 highlighted that Redis session invalidation was decoupled from the primary IAM database transaction.

2. User Stories & Acceptance Criteria

US-101: Synchronous Token Invalidation ONEHR-115

As an Enterprise IT Admin, when I demote an employee in Okta or Google Workspace, their active session in OneHR must be terminated within 200ms.

  • Webhook listener on /api/v2/iam/events processes demotion payloads.
  • Pub/Sub broadcast to all regional API gateways invalidates Redis token caches.
  • Next client HTTP request receives HTTP 401 with payload { "code": "SESSION_REVOKED" }.
US-102: Audit Trail Event Emission ONEHR-116

As a Compliance Officer, I must have an immutable audit log detailing every token invalidation event with timestamp, actor IP, and affected tenant ID.

3. Non-Functional Requirements

  • Latency: Token purge propagation must complete in < 200ms across 99th percentile.
  • Reliability: Zero dropped demotion events. Failures must route to Dead Letter Queue (DLQ).
  • Security: All revocation events signed with HMAC-SHA256.
